Java'nın temelleri

Hedef: Java kodunun çalışan programa nasıl dönüştüğünü (JDK, JRE, JVM, bytecode) anlatabilmek; tür, Scanner, printf, if, switch, döngü, dizi ve metot içeren kısa programların çıktısını kâğıt üzerinde doğru bulmak.

1.1 Java nedir, kod nasıl çalışır? sınavda çıkabilir

Java hem bir programlama dilinin hem de o dilde yazılan programları çalıştıran platformun adıdır. "Java kurmak" iç içe üç katman kurmak demektir:

JDK · Java Development Kit: javac derleyicisi ve geliştirme araçları + JRE
JRE · Java Runtime Environment: standart kütüphaneler + JVM
JVM · Java Virtual Machine: .class dosyasındaki bytecode'u çalıştıran sanal makine

Kod yazacaksan JDK kurarsın; JRE ve JVM onun içinde gelir. Yalnızca hazır bir Java programını çalıştırmak için JRE yeter.

İşlemci yalnızca makine kodunu anlar. Kaynak kodu makine koduna çevirmenin iki klasik yolu vardır, Java ikisinin karışımını kullanır:

› işlemcinin beş işi

Her program sonunda bunlara iner: aritmetik ve mantık (toplama, bit işlemi), karşılaştırma, bellek erişimi (okuma/yazma), dallanma (koşula göre başka komuta geçme), dış dünyayla alışveriş (klavye, ekran, disk, ağ).

Sözdizimi (syntax) kodun biçimidir: hangi işaret nereye gelir. Anlambilim (semantics) o biçimin ne yaptığıdır: kod çalışınca ne olur. Türkçe gibi doğal diller belirsizdir; işlemci tek anlamlı talimat ister, bu yüzden programlama dili kullanırız. "Yüksek seviye" kolay demek değildir; donanım ayrıntısından uzak demektir.

Paradigmalar ve "nesne tabanlı mı, yönelimli mi?"

Paradigma programı düzenleme ve onun hakkında düşünme üslubudur; dil değildir, bir dil birden çok üslubu destekler. Buyurgan (imperative) kod adımları tek tek yazar (for + sayaç), bildirimsel (declarative) yalnızca ne istendiğini söyler (SELECT COUNT(*) FROM urun WHERE stok <= 5). Aynı görev Java'da üç üslupla yazılabilir: yordamsal (veri ayrı, işlem ayrı), nesne yönelimli (kuralı ürün bilir: u.kritikMi()), fonksiyonel (stream().filter(...).count()).

1.7 switch ile menü

✓ ok gösterimi ( -> )

Java 14 ile geldi; derste bu yazım kullanıldı. Yalnız eşleşen case çalışır, break gerekmez. Hiçbir case tutmazsa default çalışır. Menünün dönmesini while (devam) sağlar; 0 seçilince devam = false.

! klasik gösterim ( : )

Her case'in sonuna break yazılır. Unutulursa alttaki case'ler de çalışır (fall-through): eşleşen case'ten başlar, ilk break'e ya da switch'in sonuna kadar devam eder.

1.8 Döngüler: çarpım tablosu, sayı tahmini, otopark

for (başlangıç; koşul; artış) kaç kez döneceği belli işlerde, while (koşul) koşul doğru kaldıkça döner. break döngüden çıkar, continue o turun kalanını atlayıp bir sonraki tura geçer.

N × N çarpım tablosu notta: sınav sorusu olabilir

Üç parça: başlık (13–17: " |" ve her sütun için %4d), ayırıcı (20–24: "----+" ve sütun başına "----"), satırlar (27–33). Dış döngü (i) satırı, iç döngü (j) sütunu seçer. İç döngü her satırda baştan başlar; toplam N × N çarpma yapılır.

Hizalama: "%3d |" 5 karakter yazar; başlıktaki " |" ve "----+" da 5 karakter. Her sütun %4d ve "----" ile 4 karakter. Adım adım ile 3'lük tabloda i ve j'nin nasıl değiştiğini izle.

Sayı tahmini

JDK, JRE ve JVM nedir, aralarındaki ilişki ne? teori

JVM (Java Virtual Machine) .class dosyasındaki bytecode'u çalıştıran sanal makinedir. JRE (Java Runtime Environment) = standart kütüphaneler + JVM; hazır bir programı çalıştırmak için yeter. JDK (Java Development Kit) = javac derleyicisi ve geliştirme araçları + JRE; kod yazmak için gerekir. İç içedirler: JDK ⊃ JRE ⊃ JVM.

Baslangic.java dosyası çalışan programa nasıl dönüşür? teori

javac Baslangic.java kaynak kodu derler ve Baslangic.class (bytecode) üretir. java Baslangic JVM'i başlatır; JVM bytecode'u yükler ve çalışırken işlemcinin anladığı makine koduna çevirir. Önce derleme, sonra JVM'de çalıştırma: buna karma yol denir.

Java neden "bir kez yaz, her yerde çalıştır" diye anılır?

javac makine kodu değil, platformdan bağımsız bytecode üretir. Aynı .class dosyası JVM'i olan her işletim sisteminde ve işlemcide çalışır; her platform için yeniden derlemek gerekmez. Bedeli: çalıştırmak için JVM kurulu olmalı.

Derleme ile yorumlama farkı nedir? Java hangisini kullanır?

Derleme çeviriyi çalıştırmadan önce bir kez yapar (hızlı, ama her platform için ayrı derleme). Yorumlama her çalıştırmada satır satır çevirir (her yerde çalışır, çeviri her seferinde). Java ikisini birleştirir: önce bytecode'a derler, sonra JVM'de çalıştırır.

Klasik (case 1:) gösterimde eşleşen case'ten sonraki case'ler de çalışır (fall-through), ilk break'e ya da switch sonuna kadar. Ok gösteriminde (case 1 ->) yalnız eşleşen case çalışır, break gerekmez.

3.1 İstisna nedir?

İstisna (exception), program çalışırken ortaya çıkan ve normal akışı bozan durumdur: sıfıra bölme, olmayan indis, null'un alanı, sayıya çevrilemeyen metin. Java bu durumda bir istisna nesnesi oluşturur ve fırlatır. Yakalayan bir catch yoksa program durur ve yığın izini (stack trace) yazar.

Derleme hatası başkadır: kod hiç çalışmaz, javac reddeder (missing return statement gibi). İstisna ise derlenmiş, çalışan programda olur. Derleyici 10 / 0'ı yakalamaz.

"İstisna nasıl fırlatılır?" sorusunun tam puanlık cevabı: tanım + throw new …Exception("mesaj") içeren bir metot + onu çağırıp yakalayan try-catch + çıktı.

İstisna (exception) nedir? Derleme hatasından farkı nedir? teori

İstisna, program çalışırken oluşan ve normal akışı bozan durumdur (sıfıra bölme, null erişimi, geçersiz indis). Java bir istisna nesnesi oluşturup fırlatır; yakalanmazsa program durur. Derleme hatası ise kod çalışmadan önce javac'ın bulduğu yazım/tür hatasıdır; program hiç oluşmaz.

Java'da istisna nasıl fırlatılır? Örnek bir metot ve onu yakalayan kod yazınız. kod

throw anahtar kelimesiyle, new ile oluşturulan bir istisna nesnesi fırlatılır. Fırlatma anında metodun kalanı çalışmaz; istisna çağıran yere geçer ve orada try-catch ile yakalanır.

static void stokDus(int adet, int stok) {
    if (adet > stok) {
        throw new IllegalArgumentException("Yetersiz stok: " + stok + " var");
    }
    System.out.println("Kalan: " + (stok - adet));
}

public static void main(String[] args) {
    try {
        stokDus(2, 5);     // Kalan: 3
        stokDus(9, 5);     // fırlatır
    } catch (IllegalArgumentException e) {
        System.out.println("Hata: " + e.getMessage());   // Hata: Yetersiz stok: 5 var
    }
}
throw ile throws arasındaki fark nedir? klasik

throw metodun gövdesinde bir istisna nesnesini fırlatır (throw new Exception("…")). throws metodun imzasında, metodun fırlatabileceği istisna türlerini bildirir (void oku() throws Exception). Checked istisna fırlatan metot ya onu yakalamalı ya da throws ile bildirmelidir.

try, catch ve finally bloklarının görevleri nedir?

try: istisna çıkabilecek kodu içerir; istisna olursa kalan satırları atlanır. catch (Tür e): o türden istisnayı yakalar ve işler; birden çok olabilir, ilk uyan çalışır, özelden genele sıralanır. finally: istisna olsa da olmasa da her durumda çalışır.

Checked ve unchecked istisna farkı nedir? İkişer örnek veriniz.

Checked istisnalar için derleyici yakalamayı ya da throws ile bildirmeyi zorunlu tutar: Exception, IOException. Unchecked istisnalar RuntimeException'dan türer, derleyici zorlamaz: ArithmeticException, NullPointerException, IllegalArgumentException.

Kurucuda istisna fırlatılırsa nesne oluşur mu?

Hayır. Kurucu yarıda kalır, new referans döndürmez, atama yapılmaz. Bu sayede kurala uymayan (ör. negatif fiyatlı) nesne hiç oluşamaz; doğrulamayı kurucuya koymanın amacı budur.

Çıktı nedir? try içinde "A", sonra 10 / 0, sonra "B"; catch'te "C", finally'de "D", sonra "E".

A C D E, her biri ayrı satırda. 10 / 0 ArithmeticException fırlatır, "B" atlanır, catch "C" yazar, finally her durumda "D" yazar, program devam eder ve "E" yazılır.

Birden çok catch varsa sıra neden önemli?

catch'ler yukarıdan aşağı denenir. Genel tür (Exception) önce yazılırsa bütün alt türleri o yakalar, alttaki özel catch'e asla ulaşılamaz; Java bunu derleme hatası sayar (exception NumberFormatException has already been caught). Özel olan önce yazılır.
